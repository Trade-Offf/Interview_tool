# 🗂️ Interview Tool — 面试评价卡片生成器

> 朋友，面试完还要对着空白文档发呆写评价？
> 把录音文字往这一扔，5 分钟拿下一张干净好看的评价卡片。

---

## 你现在是不是这样？

- 面完试坐在那儿，脑子里都是候选人说的话，不知道从哪开始写
- 写出来的评价全是流水账，领导看了一脸问号
- HR 催你出结论，你还在 Word 里调格式
- 每次面试评价格式不一样，留档乱七八糟

**这个工具就是来解决这件事的。**

---

## 能做什么

给 Agent 三样材料——**候选人简历 + 岗位 JD + 面试会议链接**（缺哪样它会问你），自动生成一张这样的卡片：

- ✅ 面试结论 Badge（通过 / 不通过 / 待定）
- ✅ **分项评分表**：按岗位加载评分维度（技术岗、财务岗一面/二面各 6 项已就绪），0-5 分打分 + 简评 + 平均分，JD 重点维度带标记
- ✅ 候选人表现段落（结合**简历一致性核查**：简历写的和面试答的对不上会被点出来）
- ✅ 优点 / 风险点双栏对比
- ✅ 综合结论
- ✅ **建议定级**（每轮单独给，如 `P6` / `中级`）+ **下一轮面试官重点考察**（一面/二面产出，供下一轮参考）
- ✅ 安排提醒（有异常情况时才出现）
- ✅ 右上角两个按钮：**一键导出高清 PNG** + **一键复制文字版评价**，方便贴进飞书审批表单

> 评分维度按岗位路由（见 `interview-card/rubrics/`）：**技术岗（R&D）、财务岗已就绪**（财务岗为 AI 起草、待 HR 最终确认）；BD/运营等岗位架构已预留、等 HR 提供评分表后逐个上线，在那之前 AI 会自主总结维度照常打分并在卡片上注明。

## 怎么用

### 标准姿势：三样材料一次给全（最省力，推荐）

```
帮我出一下 Rico 的一面面评

[拖入简历 PDF]
[粘贴 JD 文本 或 JD 飞书文档链接]
[甩一个妙记链接 或 粘贴逐字稿]
```

Agent 会：从妙记链接自动拉逐字稿（装好 lark-cli 并授权后全自动，见下方说明）→ 从简历提取候选人信息 → 从 JD 识别岗位并标注重点考察维度 → 逐项打分 + 简历一致性核查 → 生成 HTML 卡片。

缺哪样材料 Agent 会主动问你，不会瞎猜。简历和 JD 不是硬性要求：没简历就跳过一致性核查，没 JD 就不做重点维度标注，卡片其余部分照常生成。

> 轮次（一面/二面/三面）必须说清楚，因为对应的评分维度不一样。

### 妙记链接自动拉逐字稿的前提

需要本机装有 lark-cli（飞书命令行工具）并完成一次授权（首次使用时 Agent 会引导你扫码授权，1 分钟搞定）。没装或授权失败也不影响使用——Agent 会退回让你手动从妙记页面复制逐字稿粘贴。

### 方式二：粘贴你自己整理的评价文字

如果你已经写好了评价草稿，格式随意，说一句：

```
帮我生成面试评价卡片：

候选人：xxx / EnglishName
岗位：xxx
轮次：一面
面试结论：通过
...（其余内容随手粘）
```

同样搞定，不是技术岗或没有打分维度的话，会自动退化成自由格式的优缺点描述。

### 卡片生成后：怎么交付
右上角两个按钮：

| 按钮 | 用途 |
| --- | --- |
| 复制文字版评价 | 一键把打分/结论/定级整理成一段纯文字，粘贴进审批表单的文字栏 |
| 导出截图 | 生成一张 PNG，插入审批表单的图片栏 |

⚠️ 飞书审批目前不支持程序化写入已有实例，**贴进审批表单这一步还是要人工做**，工具帮你省的是"看逐字稿 + 手写评价 + 打分"这一大块。

### 二面/三面怎么衔接上一轮
一面卡片里的"下一轮面试官重点考察"，把这段话转给下一轮面试官参考即可（目前靠人工转达，没有做自动传递）。

## 安装方式（1 分钟）

把 `interview-card/` 目录复制到你本地 Cursor 的 skills 文件夹：

```bash
# macOS / Linux
cp -r interview-card ~/.cursor/skills/

# Windows（PowerShell）
Copy-Item -Recurse interview-card $env:USERPROFILE\.cursor\skills\
```

重启 Cursor，完成。之后直接在对话里说"生成面试卡片"就行，不用记其他命令。

生成的文件默认保存在 `~/Desktop/面试评价/{岗位}/` 文件夹（**按岗位自动分类**），文件名自动带岗位、轮次和候选人名字，例如：

```
~/Desktop/面试评价/前端/面试评价_前端_一面_Rico.html
~/Desktop/面试评价/财务/面试评价_财务_二面_Amy.html
```

## 文件结构

```
interview-card/
├── SKILL.md          ← Cursor Agent 读的指令（输入收集 + 逐字稿管道 + 解析规则）
├── template.html     ← 卡片的 HTML/CSS 设计模板（所有岗位共用）
└── rubrics/          ← 岗位评分规则库
    ├── _index.md     ← 岗位注册表（什么岗位用哪套维度）
    ├── rd.md         ← 技术岗（已就绪）
    ├── finance.md    ← 财务岗（AI 起草，待 HR 确认）
    ├── bd.md         ← BD（占位，待 HR）
    └── operation.md  ← 运营（占位，待 HR）
```

## Roadmap

- ✅ v1：逐字稿 → 评分卡片（技术岗一面/二面）
- ✅ v2：三输入标准化（简历 + JD + 会议链接）、简历一致性核查、多岗位 rubric 架构
- ⏳ v2.x：HR 每补齐一个岗位评分表就上线一个（BD → 运营 → 风控 → 实习生），只需新增一个 rubric 文件；财务岗已由 AI 起草，待 HR 确认转正
- ⏳ v3：面试跟踪表集成（待表格链接）

## 注意事项

- 候选人卡片（生成的 HTML 文件）含个人信息，**请不要上传到公开仓库**
- 导出截图功能依赖 html2canvas CDN，需要联网；复制文字版评价用的是浏览器 clipboard API，本地打开一般也能用
- 不要改 `template.html` 里的 `:root` 色板变量，否则整体风格会乱掉
- 评分维度已就绪的岗位见 `rubrics/_index.md` 注册表；未就绪岗位和三面走 AI 自主总结维度的降级模式，卡片上会注明
- 简历、逐字稿属于候选人隐私材料，用完即删，同样不要进仓库
- 回填审批流程做不到自动化（飞书审批 API 不支持写入已有实例），生成的图片/文字仍需要人工贴进审批表单
